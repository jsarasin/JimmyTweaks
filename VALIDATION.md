### Messages communication-failure recovery — November 2, 2026

Investigated recorded `com.apple.MobileSMS` gestures. The November 1 log contains move/resize sequences ending normally interspersed with resize failures reporting AX cannot-complete (`-25204`). The old update path cancelled on the first failed read or setter and inherited the process-wide 50 ms messaging timeout. Apple's installed SDK headers confirm that system-wide timeout settings affect the whole client process and that per-element overrides apply only to that exact AX object. The log alone cannot establish which request failed or whether a timed-out setter had already completed.

Active frame updates now set a 100 ms per-call override on the exact target window. One cannot-complete response permits a fresh-frame reconciliation with up to 250 ms per call, within a 450 ms total budget. Each request uses at most the remaining budget; generation/cancellation is checked before reads and writes. Recovery recomputes the original absolute desired frame rather than repeating a movement delta, and restores the target's inherited timeout on every exit. Permission failures, unsupported operations, invalid elements, and exhausted recovery remain terminal. Target admission retains its existing deadline. Rate-limited retry/failure diagnostics identify read.position, read.size, write.position, or write.size without recording window titles or contents.

New deterministic regressions reproduce a 150 ms setter failing under the old allowance and succeeding through the new bounded recovery.
